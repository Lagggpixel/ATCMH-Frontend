# Sweatbox feedback and Discord notifications

Finishing an attempt saves feedback and archives the session in one database transaction. Staff can amend general and position feedback in the replay; position feedback is restricted to recorded participants of that position. DMs are best effort and are not retried. Account settings control feedback and assignment DMs independently. The notifier resolves the current active Discord identity and skips missing, inactive or merged historical identities when replay ownership no longer matches. No feedback text is sent over Discord.

Before enabling notifications on a MariaDB installation, take a schema recovery backup and apply [the simulator schema](../sql/schema.sql) to the ATCMH LMS database. It includes the notification preferences and replay position feedback tables. Confirm the application database identity has the required table permissions. Deploy the backend with the recipient-resolution and feedback DM routes before the frontend. The frontend skips notifications when resolution is unavailable. The two components share the existing internal service-key configuration and public origin. The existing radar redirects remain in force.
