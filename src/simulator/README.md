Winds Aloft loads a display-only Open-Meteo forecast at nine points around the training airport. ## Magnetic headings and missed approaches

Controller heading instructions, drag-vector labels, aircraft heading displays, scenario heading inputs and spawn heading inputs use magnetic north. Aircraft `heading`/`targetHeading`, runway endpoints, flight-plan/hold geometry and `RadarApproach.missedHeading` remain true-north values internally and in saved snapshots. Convert magnetic instructions to true only when assigning lateral guidance; convert true geometry to magnetic before displaying or composing a drag heading. Stored aircraft state and recorded replay frames are never reconverted on load. Altitude-only instructions retain the current lateral target and ongoing turn.

Every supported airport has a pinned WMM-2025 declination at its origin/elevation, computed for 22 October 2026 with east-positive variation (`true = magnetic + variation`). The small generated table is used by both client and server; the model library is a development dependency only. `npm run data:magnetic` regenerates it and `node scripts/generate-magnetic-variation.mjs --check` verifies it. Adding an airport requires regenerating this table; missing variation fails explicitly. Runway identifiers are never used to estimate variation. This is a fixed airport-level training model, without in-sector magnetic-field or wind variation.

The existing 35-degree ILS intercept limit compares true aircraft heading against true localizer geometry. Automatic missed approaches retain an explicit configured procedural heading; a controller's altitude-only missed instruction keeps the existing lateral target. A pilot's missed-approach report makes both Vectoring Instructions and Missed Approach Instructions available as contextual replies. Missed instructions remain valid after subsequent ordinary vectors until a new approach clearance. Automatic missed-approach reasons remain trainer-only.

Events can run at an exercise time, after a latched condition and delay, or on instructor release. Conditions include reaching a hold point/location, tuning a frequency, entering a pattern leg and completing another event. Actions include spawning/removing traffic, sending a catalog pilot request/custom transmission, applying a staff manoeuvre and displaying a private instructor note. An event's ordered actions commit together; an invalid action blocks the entire event with a visible reason. Staff may retry or skip it. Same-time events follow the authored list order. Requests arrive unread through the existing radio/log pipeline; Go Around starts its announced manoeuvre, while other requests do not execute aircraft instructions; staff still choose Readback, Readback & assign or Unable.

**Test** rehearses the current draft locally without database writes. **Publish** creates an immutable numbered revision; later draft edits never alter existing sessions or attempts. The test panel can launch the latest published revision as a full shared session for controller/readback testing. Each attempt creates new aircraft identifiers and resets messages, event outcomes and exercise time.

Sessions launch a selected published revision and accept authorized mentees through their session link or code. Each exercise has one control seat and one mentee seat. There is no per-mentee assignment or attempt allowance.

The authoritative server scheduler advances only on exercise time. Pause freezes events; reload/reconnection preserves their persisted outcomes and does not replay them. Closing all pages stops offline catch-up. Future traffic definitions, event actions and instructor notes remain server-private; mentees receive live traffic and messages. The staff Timeline drawer shows event states and manual controls.

Delayed updates recover all elapsed movement while a participant's 15-second connection lease remains valid. Recovery uses the ordinary 200 ms stream cadence, applying scenario events and automatic readbacks between steps so engine time limits cannot discard movement. An expired lease or a session with no participants resumes at its saved state without advancing the offline interval.

**Restart attempt** archives the current exercise/events, starts a new attempt and restores the pinned revision at 00:00 with its existing seats. Stale/repeated lifecycle requests cannot affect the new attempt. **Finish attempt** freezes the exercise and saves its snapshot, event results and optional mentee feedback. Ending a session archives any active attempt before deleting the live session/link; published revisions and attempt history remain. Assessment is manual: finishing an event list does not award a pass, and this milestone has no automatic grading, replay viewer or notification delivery.

## Radio audio

Both views include Audio on/off and Voice controls. Playback defaults on; the explicit on/off choice is remembered in browser local storage per account and role. Online permission and voice selection remain per tab. A playback failure does not overwrite the saved choice. Device voices may load after startup; new transmissions wait for them automatically. If the browser blocks autoplay, the next click or key press in the simulator retries the queued transmission without muting audio or requiring an off/on toggle. Both roles hear new Ground and Tower transmissions regardless of the selected frequency. Published ATIS changes automatically queue the full published text. Switching frequencies, new messages and manual replays preserve the current transmission and queue. Repeated snapshots, initial history and reconnection history do not replay old messages or ATIS. Muting, reset, disconnect and leaving the page stop pending speech. A staff Pause suspends speech and retains new pilot requests for playback on resume.

Mentee frequencies count aircraft with an unanswered pilot request on that channel. The frequency selector and strip Commands backgrounds pulse #FFF600 yellow until a substantive controller response. The aircraft icon itself pulses between its normal color and #FFF600 without a flashing background. Opening a log does not clear request attention; Standby retains it. Reduced-motion preferences use steady #FFF600. Readbacks, assignments and Unable replies to commands remain in the log/audio but never add request counts or attention, including restored snapshots from previous versions. Strips show callsign, runway and aircraft type. Staff controls include a global message log across frequencies and an aircraft log for the selected traffic, including its messages on previous frequencies. These read-only logs do not acknowledge requests.

Voice settings provide Kokoro and browser voice selection, speed, volume, Test voice, Replay last message and Stop speaking. The mentee ATIS view can read only the published ATIS. Runway numbers and frequencies use digit-by-digit pronunciation. Voice, rate, volume and online-voice consent stay in the current tab; the account/role’s on/off choice is remembered in this browser.

Callsign speech reads airline numbers digit by digit (Speedbird 104 becomes "Speedbird one zero four") and registration letters phonetically (N714KG becomes "November seven one four Kilo Golf"). This applies to transmissions and manual replay; message logs retain the original callsigns. Compact airline names such as Speedbird104 and alphanumeric flight suffixes use the same rules. Feet altitudes use cardinal words (4000 becomes "four thousand"); flight levels, runway numbers and frequencies retain their digit pronunciation. Radar check-ins contain only callsign and current altitude. Approach requests display `Speedbird 1, requesting ILS approach at EGPH` and speak the initialism as letters and the airport as Edinburgh.

Speech defaults to Kokoro Emma at **1.3×**, with George and Heart also selectable. A dedicated browser worker generates whole-message PCM locally; quiet outer envelopes are trimmed and internal silent gaps are capped at 120 ms before the radio effect; 350–3200 Hz filtering, soft saturation, subtle static and squelch reproduce the approved radio samples. Speed and volume controls apply to subsequent transmissions. Browser voices remain selectable and automatically take over if model loading, inference or audio playback fails. Automatic fallback uses only local English voices; an online browser voice still requires the existing per-tab permission and explicit selection. The current tab shows preparation/fallback status. The public model, voice files, runtime and licence notices are included in production images; browser asset requests stay on the application origin. ## Exercise controls

- Select traffic in the staff list to edit callsign, aircraft type, frequency, runway, altitude, pattern, landing outcome, heading or speed. Spawn airborne/ground traffic, reposition it, or remove it. Reset restores the sample exercise after confirmation.

- Staff use the same drag-and-taxi editor as trainees. Press and hold a ground aircraft on the scope and drag it to a taxiway, stand or runway, or use **Plan on scope** in Routes to start a route to the chosen runway. Routing follows connected OSM taxiway/stand centerlines, rejects aircraft too far from that network, excludes the runway protected area and ends at the runway's hold-short point. It does not invent a straight-line shortcut when the snapshot has no connected route. Drag the route's end or the green line to reshape it, tick Hold on any row, then **Start Taxi** (or **Start Pushback** for engine-off traffic) applies it as a pilot action on any frequency, without a radio message or Contact Tower when ready. Taxi stops at each unreleased hold and the route destination; Cross Runway releases the next hold. The scenario editor uses the same editor and **Save Route** stores it as the aircraft's seeded taxi path. Taxi routes and displayed flight plans are separate.

- Flight plans are built from the airport's navigation catalogue rather than drawn. Type a route such as `TLA DCT GOW` (fixes, SIDs, STARs and approaches by name; `PROCEDURE.TRANSITION` picks a transition, otherwise a neighbouring fix naming one, then the first), or search and select waypoints and procedures. Repeated fix names resolve to the one nearest the previous fix. Drag a fix, or use its menu, to reorder, edit or remove it. Live reordering keeps a radar aircraft flying to the fix it was already heading for. A selected aircraft displays its plan in the mentee scope; deselection removes that overlay. Ground and Tower plans do not steer traffic.

- Mentee ATC panels queue supported commands for staff response. **Readback** acknowledges without changing movement; **Readback & assign** acknowledges and executes the stored instruction once; **Unable** declines without executing. Assignment revalidates current frequency, aircraft state and routes. Old snapshots without stored instructions remain readable and can be assigned manually through flight controls.

- **Automatic** applies to all aircraft. Every new session, import and scenario launch starts on, regardless of legacy account defaults. Staff can turn it off for that session; reconnecting, Reset and restarting an attempt preserve that explicit session setting. When enabled, the latest pending instruction is acknowledged and assigned after 1.5 exercise seconds. Pause freezes the delay; manual replies and newer commands supersede queued replies, and disabling cancels them. Enabling also queues existing pending instructions. Invalid assignments receive Unable with the reason; manual retunes cancel automatic assignment of the old-frequency command. Replies are logged and spoken without becoming requests. Automatic also drives the intention-based requests described below.

- Pushback approvals with a cardinal tail direction use the same queue/readback flow. Assignment reverses the parked aircraft at up to 3 KT onto the mapped taxiway behind its nose, then turns the tail along that centerline in the requested direction and stops. An aircraft without a reachable mapped taxiway behind it cannot assign pushback; check its stand position and orientation. This is simple training motion, not a model of individual stand pushback procedures.

- Final supported command choices send immediately from the message list, without a second confirmation panel. Invalid choices show their validation reason and remain disabled. Unread pilot messages belong to their original frequency and retain read state across transfers; an open extended panel marks new messages on that frequency read. Both frequency logs include all transmissions, with the other frequency in gray. Off-frequency aircraft symbols remain visible, but their tags appear only while selected.

- The staff view uses one unified radar with Ground and Tower traffic visible together, a traffic roster and a contextual bottom dock. It has no frequency tabs or ATIS editor. Choose Pilot messages, Flight controls, Routes & position or Aircraft details for the selected aircraft. Runway-specific pilot requests include a separate requested-runway selector and preview; sending a request does not change the aircraft’s assigned runway.

- Crossing, hold-short, takeoff, lineup and landing/option runway lists put the strip runway first, directly below Back. Pattern-entry and taxi destination lists retain their normal order. Open submenus follow updated assignments.
- Takeoff clearances can be sent before a pilot request or runway placement. Readback & assign calculates an A* ground route, taxis onto the runway at the assigned entry, aligns with its centerline, then accelerates to rotation. Intersection departures retain their entry through lineup, takeoff and reload. Entries with insufficient remaining distance under the simulator acceleration model are rejected without back-taxiing. Invalid unmapped ground routes still require staff repositioning before assignment. Make Right/Left Traffic sets the departure pattern; option clearances apply their requested hand after the touch-and-go, preserving the current circuit until touchdown.

- Tower Sequencing provides numbers 2–8 and source-defined follow-traffic legs. Option/landing clearances include numbers 1–8; pattern entries support sequencing. Sequence commands resolve the valid preceding aircraft on the same runway. Pattern traffic extends downwind and adjusts base/final speed to follow it; general conflict avoidance remains outside this prototype.

- The selected staff aircraft shows its projected movement in gold, active circuit in blue, and the opposite circuit dotted. Frequency is always available beside the selected callsign. Both roles animate the same kinematics at display frame rate between compact authoritative motion updates; message history is shared only when it changes.

- Unsupported operational choices remain browsable with an explanation and no enabled Send action. Report User is omitted; guard warnings are exercise transmissions without automatic retuning or external actions. Procedure routes, fixes, airspace and winds aloft are visual demonstrations, not navigational data.

- ATIS edits remain drafts until Publish. Selected ATIS tiles use white borders; unselected borders are gray. Runway text color represents wind independently of selection: green headwind, amber when crosswind dominates, red tailwind. Other tile text remains neutral. Procedure selection previews all overlays only while the menu is open with no selection; selected overlays persist after closing. Opacity affects procedures alone.

The pure engine in `engine.ts` uses fixed simulation steps, gradual turns/speed changes, a continuous five-leg pattern with turn anticipation and runway-centerline final interception, plus simple runway rollout. Ground steering in `ground-movement.ts` anticipates turns without snapping aircraft to corners. Taxi and lineup traffic slow or stop behind traffic on their upcoming route with a .045 NM (about 83 m) minimum gap, and resume when it clears. Spacing is independent of frequency and roster order, and shares the same rules with display prediction. Controller holds remain explicit. Defaults are centralized in `model.ts` (1,500 ft AGL, 15 KT taxi, 3 NM pattern width). The default circuit establishes final about 4.5 NM from the threshold; its base corner includes the turn radius so aircraft do not finish joining almost a mile closer in. Heading overrides suspend pattern navigation. A runway change preserves position, pattern leg/hand and heading overrides. Crossing and merging routes reserve a deterministic winner until it clears the shared corridor, preventing mutual taxi waits. Same-route queues keep their following gap. Give way assigns a named priority aircraft; opposing traffic uses a mapped alternate when available and otherwise remains separated. Airborne collision avoidance and realistic aircraft performance remain outside this prototype.

Airborne speed targets are IAS: 250 kt Inbound outside/leaving the pattern, 220 kt on upwind/crosswind/downwind (210–230 kt), 180 kt on base (180–200 kt), 180 kt outside 4.5 NM final, 160 kt at or inside 4.5 NM final (140–180 kt), and Vref 135 kt at or inside 2 NM. Takeoff and go-around use the combined upwind/crosswind/downwind phase. The engine ramps at 3 kt/s instead of changing speed instantly. The trainer's Airspeed ribbon and each scenario aircraft's Phase speeds settings accept a fixed positive whole IAS target per phase. Blank fields persist as null and restore that phase's automatic defaults. Fixed phase targets also provide their own sequencing speed floor; other phases remain automatic. Scenario revisions retain the optional `speedTargets` map for initial and scheduled traffic, and each session receives its own copy.

A trainer speed maneuver sets the optional `speedMode` to `manual`, retaining the global requested target across leg changes. Selecting Auto/Semi-auto resumes the configured phase profile without discarding its settings. Editing a phase also resumes the profile. Older snapshots and scenario seeds without these fields use automatic speeds; existing authored speed maneuvers still select manual mode. Ground movement retains taxi/rollout speeds. These are simplified training kinematics: the IAS number also drives map motion without a separate TAS, wind or atmospheric model.

## Banked flight turns

Local circuits and radar vectors/routes/approaches use the same bank-limited flight model. Aircraft roll toward at most 25° left or right bank at no more than 6° per exercise second, then anticipate rollout to finish on the assigned heading. A reversed clearance rolls continuously through wings level. Turn rate varies with modeled airspeed; waypoint/circuit anticipation uses the corresponding radius and roll-in distance. Ground steering retains its separate taxi model.

The optional signed `bankAngle` is authoritative motion state and persists through snapshots, prediction, reload and replay interpolation. Older snapshots start wings level. Direct aircraft edits cannot change bank. No relational schema migration is needed. Coordinated-turn rate follows [FAA PHAK chapter 5](https://www.faa.gov/sites/faa.gov/files/regulations_policies/handbooks_manuals/aviation/phak/07_phak_ch5.pdf).

### Command behavior

Airport-in-sight instructions arm a one-time automatic pilot report when the destination is at most 15 NM away and within 90 degrees either side of the aircraft heading. Automatic must be enabled. The instructor can also transmit the pilot report manually.

Cleared takeoffs use a rolling runway-entry alignment; Line up and Wait still stops. Immediate takeoff, expedited crossings, back taxi and runway exits use faster ground targets while retaining mapped turns, runway holds and traffic spacing. Back taxi follows the selected runway centerline; its Ground handoff occurs only after taking a mapped exit. Progressive turns use the next connected taxiway junction, and Follow Aircraft Ahead tracks a selected aircraft and its route. Exit-and-cross/hold instructions plan the continuation to the named runway. Missing mapped connections produce an explanation instead of a fabricated path.

Own navigation, Continue as filed and flight-following approvals resume the unflown flight plan. Expect Approach with Continue as filed restores route guidance while retaining the expected approach. Approved diversions replace the destination and route; Expect Vectors retains heading guidance until a vector or on-course clearance. Destination names and coordinates are configured in Radar navigation setup, in nautical miles east/north of the exercise origin.

STAR descent follows instructor-configured arrival waypoints, crossing altitudes and speeds; it requires an arrival name and altitude constraints. These are exercise data, not an imported navigation database. Explicit vectors/altitudes override descend-via guidance. Holding uses the assigned fix/inbound course, selected turn direction, bank-limited half turns and timed outbound legs (60 seconds at or below 14,000 feet; 90 seconds above), with assigned altitude and holding speed caps. Exit Hold resumes the remaining route. Tower speed instructions persist, release at the specified final distance, and adjust toward compatible traffic ahead.

All new motion and command state survives session snapshots, prediction and replay. No database migration is required.

Source/provenance and remote storage are recorded in the shared-assets deployment documentation.
